3. Same-network check

Are the two devices on the same network? Browsers hide real local addresses behind random .local names, and a secure page may not call a plain-http address, so this app shows what the browser exposes and compares the two devices once the link is open.

USB tethering / hotspot: what to do when Wi-Fi blocks device-to-device links
  1. Many office Wi-Fi networks use “client isolation”, which stops two devices on the same Wi-Fi from talking to each other. The direct link then fails even though both are online.
  2. USB tethering: plug the tablet into the PC with a normal data cable. On the tablet open Settings, Network, Hotspot and tethering, and switch on USB tethering. This is a normal user setting and needs no developer mode. Work-managed devices may have it switched off by policy; if so, say so in the report and do not try to bypass it.
  3. Hotspot: only if company policy allows it, switch on the tablet or PC hotspot and join the other device to it. The two devices are then on a private network of their own.
  4. After tethering or joining the hotspot, choose that network in the drop-down at the top, reload this page on both devices and repeat section 2.
  5. If the link works only on tethering or hotspot, ITN sync can still be “plug in, open both, click sync”. The corporate web filter does not see this local traffic, but the pages themselves still load from your allowed github.io address.

4. USB

What the browser can see over USB (WebUSB). This only lists devices; it never changes any setting.

Why a tablet in file-transfer mode will not show up

When the PC shows the tablet in Windows Explorer, the tablet is using MTP (media transfer). MTP is a transfer protocol, not a drive or folder. Browsers cannot talk MTP, and WebUSB blocks the device classes that Windows already uses for it. The only way to make a phone or tablet reachable from a web page over USB is USB debugging (ADB) or similar developer settings. This app does not try to turn any of that on and does not need it. Dragging files in Explorer keeps working; it just cannot be driven by a web page.

7. Same-origin tabs and database

Checks tab messaging and the browser database that ITN’s existing manual flows use. For the cross-tab part, open this page in a second tab, then press the button.

About / what this app does NOT do

  • It sends nothing to any server. The page makes no network requests of its own. The only exception is the optional STUN box, which is off unless you tick it.
  • It stores nothing. Nothing is kept after you close the page. Test files are created in memory or in private browser storage and deleted straight after. The only thing the browser keeps is a tiny service worker that exists so the Share target can work; it holds no files and no pages.
  • It reads no ITN data, contains no ITN code and uses only random test data.
  • It does not turn on developer mode, USB debugging or any security setting, and does not try to get around the company web filter.
  • It does not upload your report. “Copy report” puts plain text on your clipboard; you paste it where you choose. The report contains no IP addresses.
